# 충남 수호대 2.15.0 학급 협동

## 배포 조건

게임 코드와 Apps Script 서버를 함께 갱신해야 한다. 서버의 `?feature=coop`가 `{ok:true,api:"coop-1"}`을 돌려주는지 확인한 뒤 게임 PR을 병합한다. 기존 서버 상태에서 게임만 먼저 배포하면 학생 신규 출격이 제한되므로 선행 배포하지 않는다.

현재 작업은 코드·모의 검증을 준비하는 단계이며 실제 서버 편집기에는 소유자의 Google 로그인이 필요하다. 로그인 뒤 기존 프로젝트의 코드를 읽어 아래 기능을 추가하고, **기존 READ_KEY·시트·배포 URL·공개 범위를 그대로 보존**한다. 학생 계정이나 실제 학생 기록으로 테스트하지 않는다.

## 합의한 동작

- 평소에는 각자 플레이해 학급 공동 성과를 모으고, 행사 기간에는 여러 반이 함께 출격한다. 종합 순위나 승패, 미참여 학생 명단은 없다.
- 전투·퀴즈·탐험 각각 하루 1칸, 총 3칸까지. 전투는 단계 완료나 판 종료(패배 포함), 퀴즈는 한 문제 이상 참여한 판의 종료, 탐험은 지역 이야기를 읽고 확인할 때 기여한다.
- 학생은 일반·오늘의 도전·행사를 합쳐 한국 시간 기준 하루 3회 신규 출격한다. 시작할 때 차감하므로 중단·패배도 포함하며 이월하지 않는다.
- 계정 단위로 서버에서 집계하므로 기기·브라우저가 달라도 같은 계정의 한도를 공유한다. 재시도는 같은 요청 ID로 처리해 중복 차감하지 않는다.
- 이어하기는 기존 출격 표를 다시 사용한다. 날짜가 지나도 원래 출격일에 귀속하며 추가 차감하지 않는다. 종료된 표·다른 계정의 표는 거부한다.
- 오프라인에서는 같은 계정의 저장된 출격을 이어할 수 있다. **새 출격은 인터넷과 학생 계정이 필요**하다. 도감·카드첩·지역 이야기는 계속 볼 수 있다. 제한 적용 전 저장본은 새 출격 표가 없어 신규 출격을 안내하며, 원본 저장 자체는 지우지 않는다.
- 교사 모드 미리보기는 학생 집계·학생 제한에서 분리된다. 학급·행사 설정 저장은 화면의 교사 모드만 믿지 않고 기존 서버 READ_KEY를 확인한다.

## 작은 변화와 큰 목표

학급 기본 인원은 25명이며 선생님이 1~50명으로 설정한다. 인원 수만큼 기여하면 정찰·회복의 작은 단계가 완성되고, 인원×3칸으로 도시 하나를 정화한다. 정찰 깃발·숲 정원과 지역 장식이 기지에 남는다. 도시 15곳은 순서대로 진행하되 연합 행사로 먼저 정화한 곳은 건너뛴다. 보상은 공동 장식이며 전투 능력치나 접속 연속 보너스가 아니다.

선생님은 수업 종료 시간을 0~180분으로 설정한다(0은 미설정). 기존 기기의 시간 설정은 학급 설정을 아직 하지 않았을 때 유지한다. 시간이 끝나면 저장하고, 다음에 이어서 할 때 출격 횟수를 다시 쓰지 않는다.

## 연합 행사

선생님이 학교·참여 학급·기간(한국 시간)·지역·공동 목표를 정한다. 목표 기본값은 참여 학급 전체 인원×3이다. 행사 시작 전에 출격할 수 없으며 종료 후 새 행사 출격도 거부한다. 행사 때는 같은 이벤트 시드·지역 경로에서 **각자 전투**한다. 같은 전투 화면을 공유하는 실시간 멀티플레이가 아니다.

행사 중의 하루 기여만 합산한다. 목표를 달성하면 설정된 모든 반의 지도에 그 도시를 정화하고 기지에 지역 장식과 행사 기념을 남긴다. 학급 기록은 선생님이 설정한 학급 순서로 표시하며, 인원당 기여와 ‘전투/퀴즈/탐험에 힘쓴 반’ 기록만 보인다. 종합 순위로 정렬하지 않는다.

## 서버 파일과 설치

- `data/cooperation.js`: 브라우저·서버가 공유하는 날짜·상한·지역 진행 규칙.
- `tools/leaderboard/cooperation-server.txt`: 서버 전용 구현.
- `python tools/build_cooperation.py`: 위 두 파일을 기존 `tools/leaderboard/Code.gs` 뒤에 합쳐 설치 파일을 갱신한다. READ_KEY의 기존 값은 빌드 과정에서 바꾸지 않는다.
- 설치 파일은 하나의 `Code.gs`다. 실제 편집기에 옮길 때는 **현재 편집기의 READ_KEY 값**을 보존한다. 공개 저장소의 안내용 기본 문자열로 실제 열쇠를 덮어쓰면 안 된다.
- Apps Script 배포 관리 → 기존 배포 수정 → 새 버전 → 배포. 새 웹 앱을 만들거나 URL·시트 접근 범위를 바꾸지 않는다.
- 기존 `계정`·`기록` 탭은 그대로 유지하며, `협동상태` 탭이 추가된다. 집계·출격 표·활동별 완료만 저장한다. 학생 목록을 클라이언트에 반환하지 않는다.

## 데이터와 검증 범위

ScriptLock으로 출격 예약·집계 갱신을 직렬화하고 요청 ID와 활동별 완료로 중복을 막는다. 한국 시간은 서버 시각으로 계산한다. 네트워크 실패는 계정별 전송 대기함에 보관하고 다시 보낸다. 지난날의 퀴즈·탐험을 다음 날 실적으로 옮기지 않는다. 읽기 캐시는 60초이고 쓰기 직후 함께 갱신한다. 화면은 열려 있을 때 20초마다 갱신하고 숨겨진 창·입력 중인 교사 설정에서는 갱신을 멈춘다.

계정과 학교·반 정보는 학생이 입력하는 기존 방식을 유지한다. 공식 재학 확인이나 게임 플레이의 서버 검증을 하는 시스템은 아니므로 평가·성적 자료로 사용하지 않는다. 대규모 실제 학교 동시 접속·Apps Script 할당량·휴대폰 실기기는 별도 검증이 필요하다.

실행: `node --test tools/*.test.mjs`. 실제 서버 계정 생성이나 학생 데이터 쓰기는 모의 검사에 포함하지 않는다. 서버 적용 뒤 공개 기능 확인·화면 확인을 하고, 정상 동작을 확인한 후 Pages를 배포한다.

## 개발 검증 기록

- 자동 검사 77개 통과: 기존 계정·해금·퀴즈·음원·전투 검사와 협동 서버·클라이언트 검사를 함께 실행했다.
- 모의 Apps Script에서 계정별 3회 합산·중복 차감 방지·KST 자정·이어하기·활동별 1칸·행사 시간·전 학급 지역 정화·교사 집계 권한을 확인했다. 실제 학생 자료나 실제 계정은 쓰지 않았다.
- 별도 DOM 검사에서 도시 15곳·활동 완료 상태·행사 시작 전 버튼·빈 이미지 경로·교사 설정 입력·HTML 문자 처리를 확인했다. 브라우저 실기기나 동시 접속 부하 검사는 아니다.
- 서버 적용 전 현재 배포 게임은 2.14.7로 유지한다.
