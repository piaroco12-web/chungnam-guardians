# 교사 로그인과 공개 배포 · 2.12.1

## 사용 방법
1. 게임 설정 → 교사 로그인 → 교사 관리 화면 열기.
2. 허용된 선생님 Google 계정으로 관리 화면에 접속한다.
3. ‘일회용 접속 코드 발급’을 누르고 복사한 코드를 게임에 붙여넣는다.
4. 코드는 2분 동안 한 번만 유효하다. 로그인은 현재 탭에서 30분 동안 유지된다. 새로고침하면 다시 로그인한다.
5. 학생 기록은 교사 Google 계정 또는 서버가 확인한 세션이 있을 때만 조회한다.

## 서버 설정
- `tools/leaderboard/Code.gs`를 기존 시트에 연결된 Apps Script 프로젝트에 배포한다.
- Script Properties의 `ADMIN_EMAILS`에 허용할 Google 계정을 쉼표로 구분해 넣는다. 빈 목록·확인되지 않은 계정은 거절한다.
- 현재 공개 웹 앱의 학생 기록 POST 주소는 유지한다. GET 학생 명단 조회와 기존 읽기 열쇠는 폐기한다.
- `Session.getActiveUser().getEmail()`로 실제 접속한 Google 계정을 확인한다. `getEffectiveUser()`를 방문자로 취급하거나, 이메일이 비었을 때 소유자로 대체하면 안 된다.
- 소유자 실행 웹 앱에서는 계정 확인에 제약이 있다. 소유자 본인의 로그인은 확인하고, 추가 교사를 허용할 때는 해당 계정으로 직접 검증한다. 식별이 안 되면 열지 않는다.
- Apps Script 편집 권한은 관리자에게만 둔다. 시트 공유 권한도 별도로 관리한다.

## 보안 범위
- 공개 코드에 고정 교사 비밀번호·읽기 열쇠를 넣지 않는다. 서버는 무작위 일회용 코드와 세션을 발급하며 해시로 캐시한다. 세션은 브라우저 메모리에만 보관하고 URL·localStorage에 넣지 않는다.
- 기존 브라우저 저장소의 교사 플래그와 읽기 열쇠는 읽어 들일 때 폐기한다. 학생 코인·카드·진행 기록은 유지한다.
- 학생 PIN의 해시도 영구 저장에서 제외한다. 새로고침·새 탭에서는 학생 계정에 다시 로그인한다. 그동안 모은 기록은 그대로 남는다.
- 학생 기록 보내기는 로그인 없는 접수 창구다. 누구나 보낼 수 있으므로 시험 성적의 근거로 쓰지 않는다. 입력 범위·수식 주입 방어·요청 ID 중복 방지를 적용했다.
- 클라이언트 게임의 수치·해금은 방문자가 자기 기기에서 바꿀 수 있다. 이를 서버의 학생 기록 조회 권한으로 인정하지 않는다.
- 실행에 필요한 JavaScript·이미지와 서버 접속 주소 자체는 공개된다. 주소를 아는 것만으로 교사 조회는 허용하지 않는다.
- `_config.yml`은 문서·도구·Apps Script 소스·원본 그림을 Pages에서 제외한다. 공개 GitHub 저장소와 과거 커밋에서는 소스가 계속 보일 수 있다. 이전 인증값은 더 이상 서버에서 인정하지 않는다.
- 공개 배포에서 민감 파일을 제거해도 방문자가 이미 내려받은 복사본을 회수할 수는 없다.

## 확인
`node tools/security-test.mjs`: 익명·잘못된 계정 거절, 코드 1회 사용/만료, 권한 취소, 세션 만료, 기존 열쇠 조회 차단, 학생 기록 중복 방지와 수식 주입 방어.
`python tools/verify_release.py`: 게임 진행·음원·그림·오프라인 실행·모바일 입력.

비밀번호나 학생 기록을 이 문서·커밋·로그에 적지 않는다.

## 통신
Apps Script의 일반 fetch 응답을 브라우저가 읽지 못하는 환경에서도 인증이 동작하도록 전용 프레임과 google.script.run을 사용한다. 게임은 자신의 프레임 트리·Google 출처·무작위 채널을 확인하며, 서버 프레임은 허용된 게임 출처에서만 메시지를 받는다. 인증 코드는 URL에 넣지 않는다. 실제 권한 판단은 서버의 코드·세션 검사이며 프레임 출처 검사만으로 인증하지 않는다. 학생 계정·코인 장부는 2.12.0 구현을 유지한다.
